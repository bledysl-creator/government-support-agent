# 정부지원사업 알림 에이전트 (CLAUDE.md)

이 문서는 정부지원사업 공고를 찾아 정리하는 에이전트가 매번 따르는 규칙입니다.
에이전트는 공고를 찾아 알리기만 합니다. 신청, 회원가입, 문의 접수 같은 행동은 하지 않습니다.

---

## 1. 목적

정부지원사업 공고를 자동으로 찾아, 우리 회사 조건에 맞는지 판단하고, 결과를 구글 캘린더에 정리한다.

---

## 2. 대상 조건 (우리 회사)

| 항목 | 조건 |
|---|---|
| 업종 | 의료기기 소프트웨어 제조업 (SaMD, 디지털 헬스케어 SW 포함) |
| 지역 | 본사: 서울특별시 서초구 / R&D센터: 경기도 성남시 분당구 (경기 지점) |
| 기업 규모 | 소기업 (중소기업기본법상 소기업) |
| 설립 연도 | 2018년 설립 (2026년 기준 업력 약 8년, 창업 7년 초과) |
| 관심 분야 | 바우처, R&D 지원사업, 인력 (채용·인건비), 교육 (임직원·재직자 교육, 중소기업 교육, 사업주훈련, 의료기기 규제·인허가 교육) |
| 보유 인증 | 벤처기업 인증, GMP(의료기기 제조 및 품질관리기준), ISO 13485(의료기기 품질경영), ISO/IEC 27000 시리즈(정보보호, 27001 등) |

지역 판단: 서울 전체·경기 전체·전국 대상이면 충족. 구·시 단위로 한정된 공고는 서울 서초구 또는 경기 성남시(분당구)일 때만 충족하고, 다른 구·시 한정이면 제외. "본점 또는 지점/사업장" 소재 조건은 성남 R&D센터로 경기도를 충족한다. "본점(주사무소)" 한정이면 서울 서초구만 해당.

업력 계산: 공고의 기준일(보통 공고일 또는 신청 마감일) 기준으로 설립일부터 계산한다.
설립 월일을 모르면 "2018년 설립"으로만 보고, 업력 7년 경계에 걸리는 공고는 "검토 필요"로 둔다.

보유 인증 활용:
- 위 인증이 필수 자격이거나 가점 요건인 공고는 그 조건을 충족한 것으로 본다. 한 줄 평에 "벤처 인증 가점"처럼 적는다.
- 위 목록에 없는 인증(이노비즈, 메인비즈, 기업부설연구소 등)이 필수이면, 보유 여부를 모르므로 "검토 필요"로 둔다.
- 의료기기 품목 허가·인증(식약처)이 필수인 공고는 품목 허가 보유 여부를 따로 확인해야 하므로 "검토 필요"로 둔다.

수집 범위: 실행일 기준 접수 중이거나 접수 예정인 공고만 본다. 마감이 지난 공고는 보지 않는다.

API 인증키는 환경변수 또는 GitHub Secrets(BIZINFO_API_KEY, DATA_GO_KR_API_KEY)에서 읽는다. 키를 문서나 결과에 쓰지 않는다.
API가 실패하면 그 수집처는 웹 페이지 읽기로 대신하고, 실행 기록에 실패 사실을 남긴다.

## 4. 판단 기준

각 공고를 아래 순서로 확인해 세 가지 중 하나로 나눈다.

### 제외 (대상 조건과 맞지 않음)

아래 중 하나라도 확실히 해당하면 제외한다.

- 지역: 신청 자격이 서울·경기 외 지역 기업으로 한정됨 (예: "부산 소재 기업", "강원 소재 기업")
- 업력: 예비창업자 전용, 또는 창업 7년 이내 등 업력 상한이 있어 2018년 설립 기업이 해당하지 않음 (예: 초기창업패키지, 창업도약패키지처럼 업력 제한이 명확한 공고)
- 규모: 중견기업·대기업 전용, 또는 소기업이 명시적으로 제외됨
- 업종: 특정 업종 전용인데 의료기기·SW·제조와 관계없음 (예: 농업, 수산업, 관광, 요식업 전용)
- 분야: 바우처, R&D, 인력, 교육 중 어디에도 해당하지 않음 (예: 시설자금 융자, 판로 행사 단순 참가, 포상·시상)
- 교육: 개인 구직자·학생·예비창업자를 뽑는 교육생 모집(예: 청년취업사관학교 교육생), 교육기관·운영기관 모집, 강사 모집
- 대상이 기업이 아님 (개인, 학생, 대학, 비영리 단체 전용)
- 마감일이 이미 지남

### 꼭 맞음

아래를 모두 만족하면 꼭 맞음이다.

- 지역: 전국 대상이거나 서울 또는 경기 기업 대상
- 업력·규모: 2018년 설립 소기업이 자격에 명확히 해당
- 분야: 바우처, R&D, 인력, 교육 중 하나에 해당
- 인증: 필수 인증이 없거나, 있어도 보유 인증(벤처, GMP, ISO 13485, ISO 27000 시리즈)으로 충족됨
- 업종: 의료기기, 헬스케어, SW, ICT, 제조 중 하나가 대상에 명시되어 있거나 업종 제한이 없음
- 마감까지 7일 이상 남음 (7일 미만이어도 다른 조건을 다 만족하면 꼭 맞음으로 두고 한 줄 평에 "마감 임박"을 적는다)

### 검토 필요

제외에도 꼭 맞음에도 확실히 들지 않으면 검토 필요다. 예:

- 공고 요약만 있고 세부 자격요건(업력, 매출, 인증 보유 등)이 첨부파일에만 있어 확인이 안 됨
- 업력 기준이 경계에 걸림 (예: "업력 7년 이내", 기준일에 따라 달라짐)
- 지역 표기가 애매함 (예: 본사는 서울인데 "경기 사업장 보유" 조건)
- 보유 인증 목록(벤처, GMP, ISO 13485, ISO 27000 시리즈)에 없는 인증이 필수임 (예: 이노비즈, 메인비즈, 기업부설연구소, 식약처 품목 허가)
- 분야는 맞지만 업종이 넓게 정의되어 있어 의료기기 SW가 포함되는지 불분명함

- 교육 공고: 기업이나 재직자를 대상으로 하지만 내용이 의료기기·SW·AI·정보보호·인허가·경영 실무와 관련이 적은 단발성 세미나

교육 분야 판단: 기업이 임직원(재직자)을 보내거나 교육비를 지원받는 공고는 교육 분야로 본다. 의료기기 RA·GMP·인허가, SW·AI, 정보보호 교육이면서 지역·업력 조건이 맞으면 꼭 맞음, 주제 관련성이 낮거나 일정만 안내된 공고는 검토 필요다.

판단이 애매하면 제외보다 검토 필요를 고른다. 놓치는 것보다 한 번 더 보는 것이 낫다.

## 5. 결과 형식

공고마다 아래 7가지를 정리한다. 모르는 값은 비우지 말고 "공고문 확인 필요"라고 쓴다.

| 항목 | 내용 |
|---|---|
| 사업명 | 공고 제목 그대로 |
| 기관 | 주관 기관 / 수행 기관 |
| 지원금액 | 기업당 최대 금액, 자부담 비율이 있으면 함께 |
| 신청기간(마감일) | 시작일 ~ 마감일, 마감 시각이 있으면 시각까지 |
| 자격요건 | 핵심 조건 2~3줄 요약 |
| 링크 | 공고 원문 URL |
| 적합도 한 줄 평 | 판단 결과(꼭 맞음/검토 필요)와 이유 한 줄. 예: "꼭 맞음: 서울 소재 의료기기 SW 기업 대상 R&D, 업력 제한 없음" |

## 6. 실행 규칙

### 실행 시각
평일(월~금) 오전 9시, 한국 시간(Asia/Seoul).

### 결과 전달: 구글 캘린더
- 꼭 맞음과 검토 필요 공고만 캘린더에 올린다. 제외 공고는 올리지 않는다.
- 공고 하나당 일정 하나를 만든다.
  - 날짜: 신청 마감일, 종일 일정
  - 제목: `[꼭 맞음] 사업명` 또는 `[검토 필요] 사업명`
  - 설명: 5번 결과 형식 7가지 항목 전체, 그리고 맨 아래에 `공고ID: <수집처>-<공고번호>` 한 줄
  - 알림: 마감 7일 전, 1일 전
- 마감일이 없거나 "예산 소진 시까지" 같은 상시 공고는 발견한 날 오전 9시 30분에 30분짜리 일정으로 만들고 제목 앞에 `[상시]`를 붙인다.
- 접수 시작일이 실행일보다 뒤인 공고는, 마감일 일정에 더해 접수 시작일에도 `[접수 시작] 사업명` 종일 일정을 하나 만든다.
- 다른 사람을 초대하지 않는다. 일정은 본인 기본 캘린더에만 만든다.
- 새로 찾은 공고가 하나도 없으면 일정을 만들지 않는다.

### 중복 제외
- 기록 파일: `data/seen_notices.json (이 저장소)`
- 공고 하나를 판단하면 결과(꼭 맞음/검토 필요/제외)와 관계없이 기록에 추가한다. 항목: 공고ID, 사업명, 기관, 마감일, 판단 결과, 처음 본 날짜, 캘린더 일정 ID(있으면).
- 공고ID는 `<수집처>-<공고번호>` 형식이다 (예: `bizinfo-PBLN_000000000123456`). 공고번호가 없으면 "기관명 + 사업명(공백·특수문자 제거)"으로 만든다.
- 같은 공고가 기업마당과 기관 홈페이지에 함께 올라오는 경우가 많으므로, 공고ID가 달라도 기관명과 사업명이 같으면 같은 공고로 보고 건너뛴다.
- 기록에 이미 있는 공고는 다시 판단하지 않고, 캘린더에도 다시 올리지 않는다.
- 예외: 이미 기록된 공고의 마감일이 연장·변경되면 기존 캘린더 일정의 날짜만 고치고 설명 맨 위에 "마감 변경: 이전 날짜 → 새 날짜"를 적는다.
- 기록 파일이 없거나 깨져 있으면, 캘린더에서 `공고ID:`로 기존 일정을 검색해 중복을 확인한다.

### 하지 않는 일
- 지원사업 신청, 회원가입, 로그인, 서류 제출, 담당자 문의를 하지 않는다.
- 공고 원문이나 첨부파일 내용을 바꾸거나 외부에 올리지 않는다.
- 이메일이나 메시지를 다른 사람에게 보내지 않는다.
- 알림(캘린더 일정)만 만든다.

### 실행 기록
매 실행 후 `data/run_log.md (이 저장소)`에 한 줄씩 남긴다:
`날짜 | 확인한 공고 수 | 꼭 맞음 n | 검토 필요 n | 제외 n | 실패한 수집처`
